# RQS-P 全天饮食质量评分规则

RQS-P（Personalized Recipe Quality Score）是一套面向**普通成年健康人群（18~65 岁）全天饮食**的规则化评分体系。

项目目标是把饮食质量评价从主观判断转化为：

```text
结构化饮食输入
→ 食物成分与营养数据汇总
→ 规则引擎计算
→ 可解释评分、等级、扣分项和优化建议
```

当前仓库主要维护评分规则文档，尚未实现完整规则引擎代码。

## 当前适用范围

当前版本只支持：

```text
evaluation_scope = "whole_day"
target_population = "healthy_adult"
```

暂不覆盖：

```text
单餐评价
儿童 / 老人 / 孕产妇
疾病管理
减脂 / 增肌
控糖 / 高血压等专项模型
```

## 评分结构

RQS-P 采用 100 分制：

| 模块                    | 分值 | 评价重点                         |
| ----------------------- | ---: | -------------------------------- |
| A. 基础营养质量         |   40 | 食物组覆盖、营养素充足度         |
| B. 限制性成分控制       |   25 | 钠、烹调油、添加糖、饱和脂肪     |
| C. 烹调、加工与食品安全 |   15 | 烹调方式、加工程度、食品安全风险 |
| D. 全天摄入总量适配     |   12 | 全天能量匹配、供能结构           |
| E. 个性化与可执行性     |    8 | 喜好食材、饮食习惯、执行难度     |

总分会转换为 A/B/C/D/E 等级，并受到最高等级限制规则约束。比如能量严重偏离、钠/油/糖严重超标、食品安全高风险、食物结构严重缺失或数据质量不足时，即使原始分数较高，最终等级也会被封顶。

## 推荐实现流程

后续实现规则引擎时，建议按以下流程拆分：

```text
1. 解析用户全天饮食记录
2. 标准化食物名称、重量、餐次、烹调方式和调味品
3. 匹配食物成分数据库
4. 汇总全天能量、营养素、钠、油、糖、食物组和风险标签
5. 按 A/B/C/D/E 模块计算原始分
6. 应用最高等级限制规则
7. 输出总分、等级、模块分、主要扣分项、优点和建议
```

推荐代码模块可参考：

```text
rule_engine/
├── engine.py              # 总评分入口
├── nutrition_score.py     # A 基础营养质量
├── limiting_score.py      # B 限制性成分控制
├── cooking_score.py       # C 烹调、加工与食品安全
├── intake_fit_score.py    # D 全天摄入总量适配
├── personalization.py     # E 个性化与可执行性
└── grade.py               # 等级划分与封顶规则
```

微量营养素（如钙、铁、钾、维生素 C）对数据库依赖较高，可以先作为可选或估算项。

## 注意事项

- 分数应由规则引擎计算，不应由 AI 直接生成。
- AI 更适合负责自然语言解析、食物重量估算辅助、结果解释和建议生成。
- 钠统一使用 `mg` 作为内部计算单位；如果只有食盐量，可用 `钠 mg = 食盐 g × 393.4` 换算。
- 个性化接受度只能微调体验，不能抵消高油、高钠、高糖或食品安全问题。
