# RQS-P 全天饮食质量评分规则

> RQS-P = Personalized Recipe Quality Score
> 当前版本用于评价普通成年健康人群(18~65岁)的全天饮食质量。
> 初始阶段不评价单餐食谱，不考虑儿童、老人、孕产妇、疾病管理、减脂、控糖、增肌等特殊场景。

---

## 1. 总体设计原则

本评分体系用于将一天饮食从“主观判断”转化为“结构化输入 + 营养数据库 + 规则公式 + 可解释输出”的量化评分。

评分不应由 AI 直接主观判断，而应由规则引擎计算：

```text
用户输入全天饮食
↓
AI / 程序解析为结构化数据
↓
匹配食物成分数据库
↓
汇总全天食材重量、食物组、能量、营养素、钠、油、糖、烹调方式等指标
↓
套用规则与公式
↓
输出总分、等级、模块分、主要扣分项、主要优点和优化建议
```

AI 的主要作用：

```text
1. 将自然语言饮食记录解析为结构化数据；
2. 将规则引擎的计算结果转化为用户容易理解的解释和建议。
```

真正的分数应由规则引擎计算，而不是由 AI 随机生成。

---

## 2. 适用范围

当前版本只支持：

```text
evaluation_scope = "whole_day"
target_population = "healthy_adult"
```

暂不支持：

```text
single_meal
children
elderly
pregnancy
disease_management
weight_loss
muscle_gain
diabetes_control
hypertension_control
```

后续可在当前全天评分结构稳定后，再加入单餐评价和特殊人群模型。

---

## 3. 总分结构

采用 100 分制：

| 模块                    |          分值 | 评价内容                         |
| ----------------------- | ------------: | -------------------------------- |
| A. 基础营养质量         |            40 | 食物组覆盖、营养素充足度         |
| B. 限制性成分控制       |            25 | 钠、烹调油、添加糖、饱和脂肪     |
| C. 烹调、加工与食品安全 |            15 | 烹调方式、加工程度、食品安全风险 |
| D. 全天摄入总量适配     |            12 | 全天能量匹配、供能结构           |
| E. 个性化与可执行性     |             8 | 喜好食材、饮食习惯、执行难度     |
| **合计**          | **100** | 全天饮食综合质量                 |

总公式：

```text
RQS-P =
A 基础营养质量分
+ B 限制性成分控制分
+ C 烹调、加工与食品安全分
+ D 全天摄入总量适配分
+ E 个性化与可执行性分
```

## 5. 全天汇总指标

规则引擎应先计算以下全天指标：

```text
total_energy_kcal
total_protein_g
total_fat_g
total_saturated_fat_g
total_carbohydrate_g
total_fiber_g
total_sodium_mg
total_cooking_oil_g
total_added_sugar_g
total_food_weight_g
food_group_amounts
food_group_count
cooking_method_weighted_score
processed_food_ratio
food_safety_risk_tags
```

钠统一用 `mg` 表示。若输入只有食盐量，则按下式换算：

```text
钠 mg = 食盐 g × 393.4
```

若存在酱油、蚝油、味精、腐乳、腌制食品、加工肉等高钠来源，应优先使用食品成分数据库中的钠含量，而不是只统计额外加盐量。

# A. 基础营养质量：40 分

```text
A = A1 食物组覆盖度 + A2 营养素充足度
```

| 子模块           |         分值 |
| ---------------- | -----------: |
| A1. 食物组覆盖度 |           20 |
| A2. 营养素充足度 |           20 |
| **合计**   | **40** |

---

## A1. 食物组覆盖度：20 分

该模块评价一天饮食是否包含足够完整的基础食物组。

| 子项               | 分值 | 计算方式                                   |
| ------------------ | ---: | ------------------------------------------ |
| 谷薯类             |    4 | 达到每日目标量得满分，不足按比例给分       |
| 蔬菜类             |    5 | 达到每日目标量得满分，不足按比例给分       |
| 水果类             |    3 | 达到每日目标量得满分，不足按比例给分       |
| 优质蛋白食物       |    4 | 鱼、禽、蛋、瘦肉、大豆制品等达到目标得满分 |
| 奶类 / 大豆 / 坚果 |    2 | 有合理摄入则加分                           |
| 食物类别多样性     |    2 | 全天食物类别足够丰富得满分                 |

通用公式：

```text
单项得分 = 单项权重 × min(实际摄入量 / 每日目标量, 1)
```

建议初始目标值可按项目需要配置：

```yaml
daily_food_group_targets:
  grains_and_tubers_g: 250
  vegetables_g: 300
  fruits_g: 200
  quality_protein_foods_g: 150
  dairy_ml: 300
  soy_products_g: 25
  nuts_g: 10
```

### A1.1 谷薯类：4 分

```text
谷薯类得分 = 4 × min(实际谷薯类重量 / 每日谷薯类目标量, 1)
```

全谷物、杂豆、薯类可作为优化建议和后续扩展指标。第一版不单独加分，避免和膳食纤维、微量营养素重复。

### A1.2 蔬菜类：5 分

```text
蔬菜得分 = 5 × min(实际蔬菜重量 / 每日蔬菜目标量, 1)
```

深色蔬菜占比可作为解释项：

```text
如果深色蔬菜占蔬菜总量较低，输出建议中提示增加深色蔬菜。
```

### A1.3 水果类：3 分

```text
水果得分 = 3 × min(实际水果重量 / 每日水果目标量, 1)
```

果汁不等同于完整水果。第一版可将果汁计入添加糖或高糖饮品风险，不建议计入水果满分。

### A1.4 优质蛋白食物：4 分

优质蛋白食物包括：

```text
鱼、虾、禽肉、瘦畜肉、蛋类、奶类、大豆制品等
```

```text
优质蛋白食物得分 = 4 × min(实际优质蛋白食物重量 / 每日目标量, 1)
```

注意：该项按食物组评价，不等同于 A2 的蛋白质克数充足度。

### A1.5 奶类 / 大豆 / 坚果：2 分

| 情况                                        | 得分 |
| ------------------------------------------- | ---: |
| 奶类、大豆制品、坚果中至少 2 类达到合理摄入 |    2 |
| 仅 1 类达到合理摄入，或多类但摄入很少       |    1 |
| 基本没有相关食物                            |    0 |

建议合理摄入阈值：

```text
奶类：≥300 mL
豆制品：≥25 g 大豆等量
坚果：10 g 左右
```

### A1.6 食物类别多样性：2 分

食物类别可按以下分组统计：

```text
谷薯类、蔬菜类、水果类、畜禽肉类、水产类、蛋类、奶类、大豆及制品、坚果类、菌藻类
```

| 全天食物类别数 | 得分 |
| -------------: | ---: |
|         ≥8 类 |    2 |
|        6–7 类 |  1.5 |
|        4–5 类 |    1 |
|        2–3 类 |  0.5 |
|        0–1 类 |    0 |

---

## A2. 营养素充足度：20 分

全天评价不使用“营养素密度 ÷ 能量比”作为唯一公式。第一版以绝对摄入是否达到每日目标为主：

```text
单项得分 = 单项权重 × min(实际摄入量 / 每日目标量, 1)
```

营养素密度可作为解释辅助，用来说明“能量不少但营养质量低”。

| 子项               |         分值 |
| ------------------ | -----------: |
| 蛋白质充足度       |            6 |
| 膳食纤维充足度     |            6 |
| 关键微量营养素覆盖 |            8 |
| **合计**     | **20** |

### A2.1 蛋白质充足度：6 分

```text
蛋白质得分 = 6 × min(实际蛋白质 g / 每日蛋白质目标 g, 1)
```

默认目标可配置为：

```text
protein_g_per_day = 60
```

### A2.2 膳食纤维充足度：6 分

```text
膳食纤维得分 = 6 × min(实际膳食纤维 g / 每日膳食纤维目标 g, 1)
```

默认目标可配置为：

```text
fiber_g_per_day = 25
```

### A2.3 关键微量营养素覆盖：8 分

第一版建议选取 4 个指标：

```text
钙、铁、钾、维生素 C
```

```text
微量营养素得分 =
8 × average[
  min(实际钙 / 每日钙目标, 1),
  min(实际铁 / 每日铁目标, 1),
  min(实际钾 / 每日钾目标, 1),
  min(实际维生素C / 每日维生素C目标, 1)
]
```

如果数据库暂时缺少微量营养素数据，MVP 可将该项配置为可选，并在输出中标记“微量营养素覆盖为估算或暂未计算”。

# B. 限制性成分控制：25 分

该模块评价全天应限制摄入的成分。

| 子项           |         分值 |
| -------------- | -----------: |
| 钠摄入         |            9 |
| 烹调油         |            7 |
| 添加糖         |            5 |
| 饱和脂肪       |            4 |
| **合计** | **25** |

---

## B1. 钠摄入：9 分

默认成人健康人群钠摄入上限：

```text
sodium_limit = 2000 mg/day
```

该值约等于食盐 5 g/day。

```text
如果实际钠 ≤ 上限：
    钠得分 = 9

如果 上限 < 实际钠 < 2 × 上限：
    钠得分 = 9 × [1 - (实际钠 - 上限) / 上限]

如果 实际钠 ≥ 2 × 上限：
    钠得分 = 0
```

若输入食盐：

```text
钠 mg = 食盐 g × 393.4
```

若输入高钠调味品或加工食品，应优先使用数据库中的钠含量。

---

## B2. 烹调油：7 分

默认成人每日烹调油参考量：

```text
cooking_oil_limit = 25 g/day
```

```text
如果实际烹调油 ≤ 上限：
    油得分 = 7

如果 上限 < 实际烹调油 < 2 × 上限：
    油得分 = 7 × [1 - (实际烹调油 - 上限) / 上限]

如果 实际烹调油 ≥ 2 × 上限：
    油得分 = 0
```

---

## B3. 添加糖：5 分

默认成人每日添加糖理想控制目标：

```text
added_sugar_limit = 25 g/day
```

```text
如果实际添加糖 ≤ 上限：
    添加糖得分 = 5

如果 上限 < 实际添加糖 < 2 × 上限：
    添加糖得分 = 5 × [1 - (实际添加糖 - 上限) / 上限]

如果 实际添加糖 ≥ 2 × 上限：
    添加糖得分 = 0
```

---

## B4. 饱和脂肪：4 分

```text
饱和脂肪供能比 = 饱和脂肪 g × 9 / 总能量 kcal
```

| 饱和脂肪供能比 |     得分 |
| -------------: | -------: |
|          ≤10% |        4 |
|       10%–15% | 线性递减 |
|          ≥15% |        0 |

公式：

```text
如果 饱和脂肪供能比 ≤ 10%：
    得分 = 4

如果 10% < 饱和脂肪供能比 < 15%：
    得分 = 4 × [1 - (饱和脂肪供能比 - 10%) / 5%]

如果 饱和脂肪供能比 ≥ 15%：
    得分 = 0
```

---

# C. 烹调、加工与食品安全：15 分

```text
C = C1 烹调方式 + C2 加工程度 + C3 食品安全风险
```

| 子项             |         分值 |
| ---------------- | -----------: |
| C1. 烹调方式     |            6 |
| C2. 加工程度     |            4 |
| C3. 食品安全风险 |            5 |
| **合计**   | **15** |

---

## C1. 烹调方式：6 分

烹调方式基础分评价的是“该做法本身对全天健康饮食的友好程度”，主要考虑：

```text
1. 是否需要大量额外油脂；
2. 是否容易形成焦糊、反复高温油脂、烟熏等风险；
3. 是否容易伴随高钠、高糖、重酱汁；
4. 是否能较好保留食材本身结构和营养；
5. 是否适合作为普通成年健康人群的常规做法。
```

注意：

```text
1. 钠、烹调油、添加糖已经在 B 模块单独扣分；
2. 食品安全风险已经在 C3 单独扣分；
3. C1 不应重复精确计算油、钠、糖，但应反映烹调方式的典型健康风险；
4. 对同一种方法，如果实际做法为少油 / 重油 / 焦糊，应选择更具体的代码。
```

对全天多个菜品，可按能量或重量加权平均。优先推荐按能量加权；如果能量数据缺失，则按可食部重量加权：

```text
全天烹调方式得分 =
6 × weighted_average(各菜烹调方式基础分 / 10)
```

| 红烧 / 焖烧，普通版本     | braise_regular                    |      5 | 常伴随油、糖、酱油和较浓汤汁；具体油钠糖由 B 模块处理。               |
| 高油酱拌 / 麻酱拌         | cold_mix_heavy_sauce              |      5 | 未必高温，但常见油脂和钠负担较高；实际油钠由 B 模块处理。             |
| 干煸 / 干炒               | dry_stir_fry                      |      4 | 高温、油脂和脱水程度通常更高，容易重油重盐。                          |
| 腌制 / 泡制 / 发酵后即食  | fermented_or_pickled_ready_to_eat |      4 | 可能有益于风味和保存，但常伴随高钠或加工属性；C2/B1 继续评价。        |
| 干锅                      | dry_pot                           |      3 | 通常重油、重盐、高温，适合作为偶尔菜品，不适合作为主体。              |
| 重油红烧 / 重油焖烧       | braise_heavy_oil                  |      3 | 方法本身高度依赖油脂和浓味调料，即使食物组完整也应明显扣分。          |
| 糖醋 / 蜜汁 / 浓糖酱汁    | sugar_glazed                      |      3 | 方法通常依赖添加糖或浓酱汁，添加糖和钠由 B 模块继续扣分。             |
| 熏制                      | smoke                             |      2 | 烟熏风味通常伴随加工和潜在风险；若为加工制品，C2 也应扣分。           |
| 盐焗 / 盐腌后熟制         | salt_baked_or_salt_cured          |      2 | 方法高度依赖盐，钠由 B1 扣分，但方式本身也不适合作为常规主体。        |
| 拔丝 / 挂霜 / 糖衣        | candied                           |      2 | 主要依赖糖和高温处理，不适合作为全天饮食中的常规主体。                |
| 油炸                      | deep_fry                          |      2 | 高油、高温，容易显著增加能量和脂肪；油量由 B2 进一步扣分。            |
| 复炸 / 反复用油油炸       | reused_oil_fry                    |      1 | 反复高温油脂风险高，应接近最低分。                                    |
| 重油烧烤 / 明火烧烤       | heavy_grill                       |      1 | 高温、油烟、焦化和腌制风险叠加。                                      |
| 焦糊 / 炭化               | charred                           |      0 | 明确焦糊时不适合作为健康常规做法，并可能触发 C3 或封顶提示。          |
| 主要为生食高风险食材      | raw_high_risk                     |      0 | 生肉、生海鲜、生蛋等不应仅作为烹调方式处理，C3 食品安全也应为高风险。 |

### C1.2 复合烹调方式处理

如果一道菜包含多个烹调步骤，应按主导健康风险选择代码：

| 情况                         | 建议处理                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------- |
| 先焯后少油快炒               | 记为 `stir_fry_low_oil`                                                    |
| 先炸后红烧                   | 记为 `deep_fry` 或 `braise_heavy_oil`，取更低分                          |
| 先煎后炖                     | 如果少油且不焦糊，记为 `braise_light`；如果重油，记为 `braise_heavy_oil` |
| 烤箱少油烤到焦糊             | 记为 `charred`                                                             |
| 火锅含大量加工丸子和重口蘸料 | C1 记为 `hotpot_clear` 或更低，C2/B1 继续扣分                              |
| 凉拌熟食                     | 记为 `cold_mix_low_oil`，储存和交叉污染风险由 C3 判断                      |
| 糖醋里脊、拔丝地瓜等         | 按主导风险记为 `sugar_glazed`、`candied` 或 `deep_fry`，取更低分       |
| 腌菜、泡菜、腐乳等           | 记为 `fermented_or_pickled_ready_to_eat`，C2/B1 继续评价                   |
| 未知烹调方式                 | 暂记为 `unknown_cooking_method`，基础分 6，并在输出中提示需要确认          |

### C1.3 评分边界

```text
unknown_cooking_method = 6
```

如果油炸、重油、烟熏、焦糊菜品只是全天少量组成，不应直接否定全天；如果其成为主体，应在 C、B 和封顶规则中共同体现。

# D. 全天摄入总量适配：12 分

当前版本中，D 模块评价全天总能量是否匹配目标能量，以及三大营养素供能结构是否合理。原先“份量合理性”中的记录完整性、食物重量 / 能量密度、进食分布等指标不再直接计分，改为进入最高等级限制规则和解释输出。

| 子项               |         分值 |
| ------------------ | -----------: |
| D1. 全天能量匹配   |            8 |
| D2. 供能结构合理性 |            4 |
| **合计**     | **12** |

---

## D1. 全天能量匹配：8 分

```text
能量比 = 实际全天能量 / 每日目标能量
```

该项统一处理全天能量不足和能量过量问题。B 模块不再单独设置能量过量项，避免重复扣分。

推荐区间规则：

|                   能量比 |           得分 |
| -----------------------: | -------------: |
|               0.95–1.05 |              8 |
| 0.90–0.95 或 1.05–1.10 | 6–8，线性递减 |
| 0.80–0.90 或 1.10–1.20 | 3–6，线性递减 |
| 0.70–0.80 或 1.20–1.30 | 1–3，线性递减 |
|           <0.70 或 >1.30 |           0–1 |

基础公式可实现为分段函数。能量目标可由用户身高、体重、性别、活动水平估算

示例：

```text
每日目标能量 = 2000 kcal

实际 1960 kcal，能量比 0.98 → 8 分
实际 1840 kcal，能量比 0.92 → 约 6.8 分
实际 1700 kcal，能量比 0.85 → 约 4.5 分
实际 1450 kcal，能量比 0.725 → 约 1.5 分
实际 2600 kcal，能量比 1.30 → 约 1 分
实际 2800 kcal，能量比 1.40 → 0–1 分
```

---

## D2. 供能结构合理性：4 分

该项评价三大营养素之间的相对供能比例，不评价蛋白质、膳食纤维或微量营养素的绝对摄入是否足够。蛋白质等营养素的绝对充足度由 A2 评价。

计算三大营养素供能比：

```text
蛋白质供能比 = 蛋白质 g × 4 / 总能量 kcal
脂肪供能比 = 脂肪 g × 9 / 总能量 kcal
碳水供能比 = 碳水化合物 g × 4 / 总能量 kcal
```

参考范围：

```text
蛋白质供能比：10%–20%
脂肪供能比：20%–30%
碳水供能比：50%–65%
```

| 情况                         | 得分 |
| ---------------------------- | ---: |
| 三项均在合理范围             |    4 |
| 1 项轻度偏离                 |    3 |
| 2 项偏离，或脂肪供能明显偏高 |    2 |
| 严重偏离                     | 0–1 |

去重原则：

```text
1. D2 不因为蛋白质克数充足而额外加分；
2. D2 不因为蛋白质供能比合理而判定蛋白质摄入充足；
3. 蛋白质、膳食纤维、关键微量营养素绝对量由 A2 评价；
4. 总能量过高或过低由 D1 评价；
5. 三大营养素供能比例失衡由 D2 评价。
```

工程实现时应使用区间扣分函数，而不是依赖人工判断。

当前版本不评价早餐、午餐、晚餐分别是否合理；单餐评分留到后续版本。

# E. 个性化与可执行性：8 分

该模块评价全天饮食是否符合用户偏好、日常习惯和长期执行可能性。个性化分只能微调体验，不能抵消严重营养、限制成分或食品安全问题。

```text
E = E1 喜好食材合理引入 + E2 饮食习惯匹配 + E3 可执行性
```

| 子项                 |        分值 |
| -------------------- | ----------: |
| E1. 喜好食材合理引入 |           3 |
| E2. 饮食习惯匹配     |           2 |
| E3. 可执行性         |           3 |
| **合计**       | **8** |

---

## E1. 喜好食材合理引入：3 分

| 情况                                     |   得分 |
| ---------------------------------------- | -----: |
| 多个喜欢食材被合理纳入，且不破坏整体结构 |      3 |
| 含 1 种喜欢食材，或引入较少              |   1–2 |
| 没有用户喜欢的食物                       |      0 |
| 喜欢食材主要以高油、高钠、高糖方式出现   | 最高 1 |

判断“合理引入”的条件：

```text
1. 食材用量没有明显过量；
2. 烹调方式不是油炸、重油、高钠、高糖；
3. 没有破坏全天食物结构；
4. 不造成限制性成分明显超标。
```

---

## E2. 饮食习惯匹配：2 分

| 情况                     | 得分 |
| ------------------------ | ---: |
| 整体符合用户日常饮食模式 |    2 |
| 部分符合                 |    1 |
| 明显不符合               |    0 |

示例：

```text
用户习惯中式家常饭菜：
米饭 / 面食 + 蛋白质菜 + 蔬菜 + 汤 / 奶类 → 更匹配
完全冷食、复杂西式轻食、难以采购食材 → 可能只部分匹配
```

---

## E3. 可执行性：3 分

| 情况                                         | 得分 |
| -------------------------------------------- | ---: |
| 食材常见、价格适中、步骤简单，全天执行负担低 |    3 |
| 一般可执行                                   | 1–2 |
| 食材难买、成本高、步骤复杂或准备时间过长     |    0 |

建议判断因素：

```text
食材是否容易购买
烹调步骤是否过多
是否需要特殊设备
成本是否明显偏高
准备时间是否过长
全天搭配是否过于繁琐
```

“替代灵活性”不进入总分，改为在建议中输出。

---

## E4. 个性化与可执行性上限规则

```text
如果 B 限制性成分控制 < 12 / 25：
    E 最高 4 分

如果 B 限制性成分控制 < 6 / 25：
    E 最高 2 分

如果 C 烹调、加工与食品安全 < 8 / 15：
    E 最高 3 分
```

最终：

```text
E_final = min(E_raw, E_cap)
```

# 7. 最高等级限制规则

为了避免严重问题被其他模块抵消，设置封顶规则。

封顶规则只处理“严重问题不能被其他模块高分抵消”的情况。普通偏差仍由 A/B/C/D/E 模块正常扣分解决。

## 7.1 能量封顶

```text
能量比 = 实际全天能量 / 每日目标能量
```

| 触发条件                | 最高等级 |
| ----------------------- | -------- |
| 能量比 < 0.80 或 > 1.20 | C        |
| 能量比 < 0.70 或 > 1.30 | D        |

说明：D1 负责能量匹配扣分；能量封顶用于避免全天能量明显过低或过高时仍被其他模块高分推到 A/B。

## 7.2 限制性成分封顶

| 触发条件                                             | 最高等级 |
| ---------------------------------------------------- | -------- |
| 钠 ≥ 2 × 每日上限                                  | C        |
| 添加糖 ≥ 2 × 每日上限                              | C        |
| 烹调油 ≥ 2 × 每日上限                              | C        |
| 钠、添加糖、烹调油中任意 2 项同时 ≥ 1.5 × 每日上限 | C        |
| 饱和脂肪供能比 ≥ 15%                                | C        |
| 钠、添加糖、烹调油任一项 ≥ 3 × 每日上限            | D        |

## 7.3 食品安全与烹调加工封顶

| 触发条件                                                                                                               | 最高等级 |
| ---------------------------------------------------------------------------------------------------------------------- | -------- |
| 存在明确食品安全高风险                                                                                                 | C        |
| C3 食品安全风险 = 0，且包含 `raw_meat`、`raw_seafood`、`undercooked_poultry`、`leftover_not_reheated` 任一标签 | D        |
| 食品安全高风险且限制性成分严重超标                                                                                     | D        |
| 油炸 / 复炸 / 重油烧烤 / 焦糊类食物能量占全天能量 ≥ 50%                                                               | C        |
| 油炸 / 复炸 / 重油烧烤 / 焦糊类食物能量占全天能量 ≥ 70%                                                               | D        |
| 加工食品 / 甜饮料 / 高糖糕点能量占全天能量 ≥ 50%                                                                      | C        |

## 7.4 基础饮食结构封顶

| 触发条件                                   | 最高等级 |
| ------------------------------------------ | -------- |
| A1 食物组覆盖度 < 8 / 20                   | C        |
| 全天缺少蔬菜且缺少水果                     | C        |
| 全天优质蛋白食物极低，且蛋白质充足度 < 50% | C        |
| 全天几乎只有单一食物组，食物类别数 ≤ 2    | C        |

## 7.5 数据质量封顶

| 触发条件                                                          | 最高等级 |
| ----------------------------------------------------------------- | -------- |
| 记录完整性 = 0                                                    | B        |
| 缺少食物重量、调味品和零食 / 饮品信息，导致钠、油、糖无法可靠估算 | C        |

说明：数据质量封顶不是判断饮食一定差，而是避免在信息不足时给出过高等级。

## 7.6 份量与进食分布异常封顶

以下指标不进入 D 模块直接打分，只用于识别异常情况并限制最高等级。

先计算：

```text
全天可食部重量 = 所有实际摄入食物重量之和
能量密度 = 全天总能量 kcal / 全天可食部重量 g
餐次能量占比 = 单个餐次能量 / 全天总能量
零食 / 甜饮能量占比 = snacks 能量 / 全天总能量
```

口径：

```text
1. 白水、无糖茶、黑咖啡不计入可食部重量；
2. 实际喝掉的汤、粥、奶、豆浆、饮料计入可食部重量；
3. 未喝完的汤汁、锅底、腌制汁不计入可食部重量；
4. 如果只能获得菜品总重量，可先按估算值计算，并在输出中标记。
```

| 触发条件                                      | 最高等级 |
| --------------------------------------------- | -------- |
| 全天可食部重量 <600 g 或 >3500 g              | D        |
| 能量密度 <0.3 kcal/g 或 >3.5 kcal/g           | D        |
| 几乎全部能量集中在一餐，最大单餐能量占比 >80% | E        |
| 零食 / 甜饮能量占比 >50%                      | D        |

实现方式：

```text
raw_score = A + B + C + D + E
raw_grade = score_to_grade(raw_score)
cap_grade = min(all_triggered_cap_grades)
final_grade = min(raw_grade, cap_grade)
```

注意：这里的 `min` 指按照等级顺序 A > B > C > D > E 进行封顶。

# 10. 测试场景

## 10.1 正常三餐

主食、蔬菜、优质蛋白、水果、奶类基本齐全，钠和油不过量。

预期：

```text
A 较高
B 较高
最终等级 B 或 A
```

## 10.2 高钠饮食

全天盐、酱油、加工食品较多，钠超过 4000 mg。

预期：

```text
B1 钠摄入 = 0 / 9
触发最高等级 C
```

## 10.3 高油但食物组完整

食物组完整，但烹调油明显超过 50 g。

预期：

```text
A 可能较高
B2 烹调油 = 0 / 7
触发最高等级 C
不能被食物结构完整性洗白
```

## 10.4 低能量高蛋白饮食

蛋白质充足，但全天能量明显低于目标。

预期：

```text
A2 蛋白质可得较高分
D1 全天能量匹配明显扣分
输出提示全天能量不足
```

## 10.5 单一饮食

全天主要只吃一种主食或单一菜品，即使能量足够。

预期：

```text
A1 食物组覆盖度低
A2 微量营养素覆盖可能低
输出提示食物种类不足
```

## 10.6 能量达标但供能结构失衡

全天总能量接近目标，但脂肪供能比明显偏高，或碳水 / 蛋白质供能比明显偏离合理范围。

预期：

```text

A2 只评价蛋白质、膳食纤维和关键微量营养素的绝对充足度
```

# 11. 注意事项

## 11.1 第一版不宜过度复杂

MVP 阶段建议优先计算：

```text
能量
蛋白质
脂肪
饱和脂肪
碳水化合物
膳食纤维
钠
烹调油
添加糖
食物类别
烹调方式
加工程度
食品安全风险
用户偏好
```

暂时可以不计算过多微量营养素，以免数据库维护成本过高。

## 11.2 食物结构和营养素充足度不能重复加分

例如：

```text
蔬菜多 → 食物组覆盖度加分
蔬菜带来的纤维、钾、维生素 C → 营养素充足度中体现
```

因此要避免再单独增加过多“蔬菜奖励分”。

## 11.3 个性化只能微调，不能洗白高风险全天饮食

核心原则：

```text
用户喜欢某种食物 ≠ 这一天饮食质量高
```

只有当喜欢食物被合理引入时，才加分。

示例：

```text
土豆 + 鸡肉 + 蔬菜 + 牛奶 + 水果 → 可以因为用户喜欢土豆而加分
炸薯条 + 香肠 + 甜饮料 → 个性化加分受限，并触发限制性成分或加工食品扣分
```
